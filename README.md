# PR Navigator

Структурированный локальный менеджер code review для сравнений в Git. Расширение помогает вести осознанную проверку изменений между двумя Git-ссылками (ветками, тегами, коммитами) без обращения к сети и без интеграции с GitHub или любыми внешними сервисами.

Всё состояние хранится локально в JSON-файлах внутри репозитория. Никаких данных наружу не отправляется.

## Возможности

- Четыре статуса проверки файла с автоматическим прогрессом.
- Обнаружение изменений между обновлениями: изменившийся проверенный файл автоматически становится «Требует повторной проверки».
- Дерево файлов, сгруппированное по статусам, со счётчиками.
- Навигация по diff встроенными средствами `VS Code` (собственная схема документов `pr-navigator`).
- Заметки двух уровней: к файлу и к строке с устойчивой привязкой по контексту ±3 строки.
- Экспорт отчёта проверки в Markdown.
- Полностью офлайн: только локальный `git` и стандартный API `VS Code`.

## Статусы

| Статус | Значение |
| --- | --- |
| `Не просмотрен` | Файл ещё не проверен. Новые файлы получают его автоматически. |
| `В процессе` | Проверка начата, но не завершена. |
| `Проверен` | Проверка завершена — только такие файлы учитываются в прогрессе. |
| `Требует повторной проверки` | Файл изменился в Git после проверки. Статус не сбрасывается автоматически. |

Прогресс: `round(Проверено / Всего)`, `0`, если файлов нет.

## Требования

- `VS Code` `^1.90.0`.
- `git` в `PATH` (расширение вызывает его через `child_process.spawn` без интерполяции строк в shell).
- `Node.js` и `npm` — только для сборки и тестов; в рантайме обязательных зависимостей нет.

## Установка

### Вариант 1. Запуск из исходников (отладка)

```bash
npm install
npm run compile
```

Откройте папку проекта в `VS Code` и нажмите **F5** (конфигурация «Запуск расширения PR Navigator»). Откроется окно `Extension Development Host` с активированным расширением.

### Вариант 2. Установка копированием

У расширения нет рантайм-зависимостей, поэтому `node_modules` не требуется:

```bash
mkdir -p ~/.vscode/extensions/local-pr-navigator.pr-navigator-0.1.0
rsync -a --exclude node_modules --exclude test --exclude .git ./ \
  ~/.vscode/extensions/local-pr-navigator.pr-navigator-0.1.0/
```

Перезапустите VS Code или выполните `Cmd+Shift+P` → «Developer: Reload Window».

### Вариант 3. Пакет `.vsix`

```bash
npm install -g @vscode/vsce
vsce package
```

Полученный `pr-navigator-0.1.0.vsix` установите через `Cmd+Shift+P` → «Extensions: Install from VSIX...» или командой:

```bash
code --install-extension pr-navigator-0.1.0.vsix
```

Пакет можно передать другим пользователям — он устанавливается без сети.

## Тестирование

```bash
npm run typecheck
npm run lint
npm test
```

Тесты (`Vitest`, 120 штук) покрывают git-интеграцию, обнаружение изменений, персистентность, якоря заметок, генерацию отчётов и жизненный цикл менеджера. Они создают временные Git-репозитории в системном каталоге временных файлов, поэтому `git` должен быть доступен.

## Использование

1. Откройте папку с Git-репозиторием в `VS Code`.
2. В панели активности слева выберите иконку `PR Navigator`.
3. В заголовке вида нажмите «Начать новую проверку», выберите базовую ссылку (от неё строится сравнение) и сравниваемую ссылку (чьи изменения проверяем). Можно ввести имя ссылки вручную.
4. Файлы появятся в дереве, сгруппированные по статусам. Клик по файлу открывает diff.
5. Отмечайте статусы через контекстное меню файла.
6. Добавляйте заметки: к файлу — из контекстного меню файла; к строке — командой «Добавить заметку к строке» в контекстном меню редактора (курсор стоит на нужной строке).
7. По мере развития ветки нажимайте «Обновить проверку» в заголовке вида — расширение пересчитает изменения и пометит устаревшие файлы.
8. «Экспортировать отчёт (Markdown)» сохраняет итоговый отчёт проверки.

Если в репозитории сохранена ровно одна проверка, при активации расширения она восстанавливается автоматически. Иначе восстановите нужную проверку командой «Открыть сохранённую проверку».

## Команды

| Команда | Где доступна | Действие |
| --- | --- | --- |
| Начать новую проверку | Палитра, заголовок вида | Выбор пары ссылок и создание проверки |
| Открыть сохранённую проверку | Палитра, заголовок вида | Список сохранённых проверок репозитория |
| Обновить проверку | Палитра, заголовок вида | Пересчёт изменений, устаревание, обновление якорей |
| Экспортировать отчёт (Markdown) | Палитра, заголовок вида | Сохранение отчёта в выбранный файл |
| Изменить статус файла | Палитра | Выбор файла и нового статуса |
| Пометить как «В процессе» / «Проверен» / «Требует повторной проверки» / «Не просмотрен» | Контекстное меню файла | Быстрая смена статуса |
| Открыть diff | Контекстное меню файла, клик по файлу | Встроенное сравнение сторон |
| Добавить заметку к файлу | Контекстное меню файла | Заметка без привязки к строке |
| Добавить заметку к строке | Контекстное меню редактора, палитра | Заметка с якорем по текущей строке |
| Заметки файла | Контекстное меню файла | Просмотр, редактирование и удаление заметок |

## Расположение данных

Состояние проверок хранится в каталоге:

```
<корень-репозитория>/.vscode/pr-navigator/reviews/
```

Каждая проверка — отдельный JSON-файл вида `review-<стабильный-id>.json`, где `id` вычисляется из корня репозитория и пары ссылок, поэтому повторное открытие той же пары ссылок возвращает ту же проверку.

Записи выполняются атомарно (через временный файл с последующим переименованием) и защищены от гонок последовательным исполнением. При чтении повреждённого JSON, неизвестной версии схемы или некорректной структуры расширение не падает: файл пропускается с понятным сообщением на русском языке, а остальные проверки продолжают работать.

**Важно:** добавьте `.vscode/pr-navigator` в `.gitignore` репозитория. Иначе JSON-файлы состояния попадут в diff и будут засорять собственные проверки (это поведение зафиксировано тестами).

## Ограничения

- Работа ведётся только с локальным Git: `fetch` и обновление удалённых веток не выполняются.
- Прогресс считается на уровне файлов, а не отдельных строк.
- Заметки хранятся локально в репозитории и не синхронизируются между участниками.
- Интеграции с GitHub и другими внешними системами нет и не предполагается.

## Структура проекта

- `src/git` — обёртка над `git` CLI через `spawn`: список ссылок, `merge-base`, `raw`-diff с детекцией переименований, чтение содержимого файла по коммиту.
- `src/review` — домен: типы проверки, статусы и переходы, расчёт прогресса, обнаружение изменений, менеджер жизненного цикла.
- `src/notes` — заметки и разрешение строкных якорей по сохранённому контексту.
- `src/storage` — атомарная JSON-персистенция, валидация схемы, список проверок.
- `src/reports` — генератор Markdown-отчёта.
- `src/providers` — дерево вида и провайдер документов для diff-сравнения (схема `pr-navigator`).
- `src/commands` — обработчики и регистрация команд.
- `test` — тесты (`Vitest`) всех перечисленных слоёв.
